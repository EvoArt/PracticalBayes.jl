Models

PracticalBayes.@model — Macro
@model function name(args...; kwargs...) ... end

Define a model. Calling name(args...) returns a Model.

Statements in the body:

  • x ~ dist: if x is a model argument holding data, x is observed and logpdf(dist, x) is added to the log-likelihood. Otherwise x is a parameter. Pass missing for an argument to make it a parameter, or bind data later with condition.
  • x[i] ~ dist: if x is a model argument, the element x[i] is observed. Otherwise x[i] is one element of an indexed family of parameters; create the container first, for continuous elements with x = Vector{paramtype(__mode__)}(undef, n) (see paramtype).
  • y .~ dists: observe every element of the argument y at once, faster than a loop. dists may be one distribution or a broadcast such as Normal.(mu, sigma). .~ cannot introduce parameters; use an array distribution with ~ for those.
  • z := expr: assign z, record it in the chain, and treat it as data, so a later z ~ dist observes it.
  • @addlogprob!expr: add expr to the log-likelihood.
  • return expr: the value returned gives back.

Discrete parameters (Categorical, Bernoulli, ...) cannot be sampled by HMC; give them a Gibbs kernel in Gibbs.

@model function linreg(x, y)
    α ~ Normal(0, 10)
    β ~ Normal(0, 10)
    σ ~ Exponential(1)
    y .~ Normal.(α .+ β .* x, σ)
end

m = linreg(x, y)
chn = sample(m, NUTS(0.8), 1000)

PracticalBayes.@static_model — Macro
@static_model function name(args...) ... end

Define a model exactly as @model does, but make build_layout default to static=true: a layout whose site records are held in a Tuple, as juliac --trim needs.

Use it for a model that will be compiled into a standalone binary. Compile time grows with the number of site records, so write an indexed family as one array distribution (x ~ MvNormal(zeros(n), I)) rather than a loop of x[i] ~.

See the trimming guide.

PracticalBayes.@addlogprob! — Macro
@addlogprob!(expr)
@addlogprob!(expr, depends=(:a, :b, ...))

Add expr to the log-likelihood. Valid only inside an @model body.

Use it for a log-density term that is not a ~ statement.

depends lists the model variables expr reads. A Gibbs HMC block that owns none of them then skips the term, which cannot change its gradient. Name every variable expr reads: a missing name silently drops a gradient term. check_depends tests the annotations. Without depends the term is always evaluated.

@model function m(data)
    a ~ Normal()
    b ~ Normal()
    @addlogprob! loglik_a(a, data) depends=(:a,)
    @addlogprob! loglik_b(b, data) depends=(:b,)
end

Sampling

StatsBase.sample — Method
sample(rng, model::Model, spl::AdvancedHMC.AbstractHMCSampler, N;
       adtype=AutoForwardDiff(), init=NamedTuple(), chain_type=SymChain,
       kwargs...)

Draw N samples from the posterior of model with an HMC sampler such as NUTS() and return them as a SymChain.

Keywords

  • n_adapts: number of warm-up iterations that adapt the step size and metric; defaults to min(1000, N ÷ 2).
  • discard_initial: iterations to run and drop before the N kept ones; defaults to n_adapts, so the chain holds N draws after warm-up. Pass discard_initial=0 to keep the warm-up.
  • thinning: keep every thinning-th iteration.
  • init: starting values by name; others are drawn from the prior.
  • adtype: AD backend for the gradient, e.g. AutoMooncake().
  • progress: show a progress meter; defaults to default_progress.
  • chain_type=nothing: return AdvancedHMC's raw transitions instead.

Parameters are reported on their constrained scale. Sampler statistics such as :acceptance_rate and :n_steps, and the :logprior, :loglikelihood and :logjoint of each draw, are included as extras. The parameters take the sampler's number type, so NUTS(0.8f0) samples in Float32 (see Run a model in Float32).

For several chains: sample(model, spl, MCMCThreads(), N, nchains).

chn = sample(model, NUTS(), 1000)
source
StatsBase.sample — Method
sample(rng, model::Model, spl::Gibbs, N; n_adapts=0, discard_initial=0,
       init=NamedTuple(), adtype=AutoForwardDiff(), save_states=nothing,
       progress=default_progress(), chain_type=SymChain)

Run N sweeps of the Gibbs sampler spl after discard_initial sweeps of burn-in, and return them as a SymChain.

Keywords

  • n_adapts: warm-up iterations for each HMC block, counted from the first sweep.
  • discard_initial: sweeps to run and drop before the N kept ones.
  • init: starting values by name; others are drawn from the prior.
  • adtype: AD backend used by every HMC block.

  • chain_type=nothing: return a vector of NamedTuples instead.

             save_states=(z = :buffer,))

PracticalBayes.NUTSthenHMC — Type
NUTSthenHMC(δ=0.8; n_leapfrog=nothing, kwargs...)

An HMC sampler that runs NUTS for the first n_adapts iterations and then fixed-length HMC with the metric and step size NUTS adapted. Each draw after warm-up then costs the same number of gradient evaluations, which keeps the sweeps of a Gibbs sampler even.

Keywords

  • n_leapfrog: leapfrog steps per iteration after warm-up. nothing takes 2^d - 1, where d is the median NUTS tree depth during warm-up.
  • jitter: draw the step count uniformly from 1:n_leapfrog each iteration.
  • Others (metric, max_depth, ...) are passed to AdvancedHMC.NUTS.

n_adapts must be given to sample.

chn = sample(model, NUTSthenHMC(0.8), 2000; n_adapts=1000)
source
PracticalBayes.AdaptiveHMC — Type
AdaptiveHMC(δ=0.8; n_leapfrog=10, kwargs...)

Fixed-length HMC that adapts its step size and metric during the first n_adapts iterations, as NUTS does, targeting acceptance rate δ. Every iteration takes n_leapfrog leapfrog steps.

Keywords

  • n_leapfrog: leapfrog steps per iteration.
  • jitter: draw the step count uniformly from 1:n_leapfrog each iteration.
  • metric: :diagonal (default), :dense, :unit, or an AdvancedHMC metric.
  • adapt: :full adapts the metric and step size; :step_size keeps the metric and adapts only the step size (see warm_start).

PracticalBayes.JitteredNSteps — Type
JitteredNSteps(L)

AdvancedHMC termination criterion for a fixed-length trajectory whose step count is drawn uniformly from 1:L at each iteration. A drop-in replacement for FixedNSteps(L) in a Trajectory{EndPointTS}. It avoids a fixed trajectory length resonating with the posterior, and costs (L + 1) / 2 steps per iteration on average.

Gibbs sampling

PracticalBayes.Gibbs — Type
Gibbs(pairs::Pair...)

A Gibbs sampler that updates blocks of variables in turn, once each per sweep.

Each pair maps a variable name, or a tuple of names, to the sampler for that block:

  • an HMC sampler (NUTS, HMC, AdaptiveHMC, NUTSthenHMC) or another AbstractMCMC sampler that works on a log density, which takes one step on the block's continuous parameters with every other variable held fixed;
  • a Gibbs kernel (PG, ConjugateGibbs or your own AbstractGibbsKernel), which draws the block's new values directly.

Every parameter of the model must be in exactly one block, and discrete parameters need a Gibbs kernel. Run it with sample; pass n_adapts there and keep it the same for the whole run.

# `pk` and `AllocationKernel` as in the `ConjugateGibbs` and `gibbs_step` examples
spl = Gibbs((:α, :β) => NUTS(), :p => pk, :z => AllocationKernel())
chn = sample(model, spl, 1000; n_adapts=500, discard_initial=500)
source
PracticalBayes.AbstractGibbsKernel — Type
AbstractGibbsKernel

Supertype of Gibbs kernels: samplers that draw a block of a Gibbs sampler directly. A subtype must implement gibbs_step. A kernel can update any block, discrete or continuous.

Gibbs calls the kernel once per sweep and never differentiates through it, so a kernel may use any code: discrete draws, exact forward-filtering backward-sampling, Metropolis proposals.

Mutable state inside a kernel must survive deepcopy, which MCMCThreads uses to give each chain its own sampler.

source
PracticalBayes.gibbs_step — Function
gibbs_step(rng, kernel::AbstractGibbsKernel, names::Tuple{Vararg{Symbol}},
            cond::ModelConditional) -> NamedTuple

Draw new values for the block names given the rest of the state in cond (a ModelConditional). Implement this for your AbstractGibbsKernel subtype.

Return a NamedTuple with exactly the keys in names. Each value must have the same type as the variable's starting value, e.g. Bool for a Bernoulli variable and Int for a Categorical one.

The call happens once per Gibbs sweep, outside any gradient computation, so the values in cond are plain numbers.

Example

A two-component mixture whose allocations z are drawn exactly given p and μ:

@model function mixture(y)
    p ~ Beta(1, 1)
    μ ~ Normal(0, 5)
    z = Vector{Bool}(undef, length(y))
    for i in eachindex(y)
        z[i] ~ Bernoulli(p)
    end
    y .~ Normal.(ifelse.(z, μ, 0.0), 1.0)
end

struct AllocationKernel <: AbstractGibbsKernel end

function PracticalBayes.gibbs_step(rng, ::AllocationKernel, names, cond::ModelConditional)
    y, p, μ = cond.model.args.y, cond.values.p, cond.values.μ
    z = map(y) do yi
        l1 = log(p) + logpdf(Normal(μ, 1), yi)
        l0 = log1p(-p) + logpdf(Normal(0, 1), yi)
        rand(rng) < 1 / (1 + exp(l0 - l1))
    end
    return (; z = z)
end

spl = Gibbs(:p => NUTS(0.8), :μ => NUTS(0.8), :z => AllocationKernel())
chn = sample(mixture(y), spl, 1000; n_adapts=500, discard_initial=500)

PracticalBayes.ConjugateGibbs — Type
ConjugateGibbs(name, family, prior, count; n=nothing, collect=identity)

A Gibbs kernel that draws the block name from a conjugate Beta or Dirichlet full conditional: the prior hyperparameters plus counts returned by count.

Arguments

  • name: the block's variable.
  • family: :beta or :dirichlet.
  • prior: (a, b) for :beta, a concentration vector for :dirichlet.
  • count: count(c) returns the counts given the ModelConditional c: (successes, failures) for :beta, a vector of category counts for :dirichlet.
  • n: for n independent draws (one per group, say), count(c, k) is called for each k in 1:n.
  • collect: with n, turns the vector of draws into the block's value.

The prior in the model should match prior; the kernel does not read it.

pk = ConjugateGibbs(:p, :beta, (1, 1)) do c
    s = count(c.values.z)
    (s, length(c.values.z) - s)
end
spl = Gibbs(:p => pk, :μ => NUTS(0.8), :z => AllocationKernel())   # see `gibbs_step`
source
PracticalBayes.PG — Type
PG(n_particles)

A Gibbs kernel that draws a Gibbs block by particle Gibbs (conditional sequential Monte Carlo) with n_particles particles, at least 2. Use it for discrete latent variables that have no exact kernel.

spl = Gibbs(:k => PG(50), (:μ, :w) => NUTS())
chn = sample(model, spl, 1000)

More particles mix faster per sweep. Each sweep re-runs the model once per particle per observation, so the cost grows with the square of the number of observe statements. For hidden Markov models and similar chains an exact gibbs_step kernel is faster and mixes better.

PracticalBayes.hmc_tuning — Function
hmc_tuning(spl::Gibbs, state::GibbsState) -> Tuple

The metric and step size each HMC block of spl has reached in state, one entry per block: nothing for a kernel block, otherwise (names, metric, step_size). metric is the inverse mass matrix as a plain array (a Matrix for a dense metric, a Vector for a diagonal one, nothing for the unit metric).

PracticalBayes.warm_start — Function
warm_start(spl::Gibbs, tuning; adapt=:step_size) -> Gibbs

spl with each HMC block starting from the metric and step size in tuning (from hmc_tuning) instead of a unit metric and a step-size search. Pair it with init = state.values to start from where the earlier run ended as well.

What warm-up then does is set by n_adapts at the sample call:

  • n_adapts = 0: the carried metric and step size are used as they are.
  • n_adapts > 0 and adapt = :step_size: the step size is re-tuned by dual averaging and the metric is kept. This is the cheap choice when the target has moved a little, since the step size is what a shift in scale upsets.
  • n_adapts > 0 and adapt = :full: the whole windowed adaptation runs again. The windowed estimate of the metric restarts from its first window, so this buys little over a cold start beyond skipping the step-size search.

:step_size needs AdaptiveHMC blocks. A NUTS block takes the carried metric and step size under :full only. A plain HMC block adapts nothing, so it is left as it is.

PracticalBayes.check_depends — Function
check_depends(model, spl::Gibbs; init=NamedTuple(), adtype=AutoForwardDiff(),

PracticalBayes.predict — Function

PracticalBayes.build_layout — Function
build_layout(model; flat=nothing, values=(), untracked=(), init=NamedTuple(),
             rng=Random.default_rng(), T=Float64, static=false) -> (layout, θ0, store0)

Run model once to find its parameters and decide where each one lives: in the flat unconstrained vector θ or in a store of constant values.

Keywords

  • flat: names to put in θ. nothing means every continuous parameter not in values.
  • values: names to put in the store. Discrete parameters must go here.
  • untracked: names in θ to leave out of invlink output.
  • init: starting values by name; other parameters are drawn from the prior.
  • T: element type of θ0, e.g. Float32.
  • static: hold the site records in a Tuple, for juliac --trim. Defaults to true for an @static_model.

Returns the Layout, the starting vector θ0 and the starting store.

julia> @model function demo(y)
           μ ~ Normal(0, 1)
           σ ~ Exponential(1)
           y ~ Normal(μ, σ)
       end;

julia> layout, θ0, store0 = build_layout(demo(1.0); T=Float32);

julia> layout.dim, eltype(θ0)
(2, Float32)

PracticalBayes.LogDensityFunction — Type
LogDensityFunction(model, layout, store=NamedTuple(), adtype=nothing;
                   θ0=zeros(layout.dim), reject_errors=false, closed_form=true)

The log joint density of model as a function of the flat unconstrained vector θ, implementing the LogDensityProblems.jl interface. Values in store are held constant.

Arguments

  • layout, store: from build_layout.
  • adtype: an ADTypes backend such as AutoForwardDiff() or AutoMooncake(), AutoPBForwardDiff, GradMode, or nothing for the density only.

Keywords

  • θ0: a vector of the type you will evaluate at; the gradient is prepared for its element type. Pass a Float32 vector for a Float32 run.
  • reject_errors: treat an error inside the model as density -Inf instead of throwing.
  • closed_form: use the closed-form gradient when the model is recognised (see is_gradmode_compatible). Set false to force adtype. Ignored for AutoPBForwardDiff, which always uses Piste.

Computation follows the element type of θ.

julia> using LogDensityProblems, ADTypes

julia> @model function demo()
           μ ~ Normal(0, 1)
       end;

julia> layout, θ0, store0 = build_layout(demo());

julia> f = LogDensityFunction(demo(), layout, store0, AutoForwardDiff(); θ0=θ0);

julia> LogDensityProblems.logdensity_and_gradient(f, [1.0])
(-1.4189385332046727, [-1.0])
source
PracticalBayes.paramtype — Function
paramtype(mode) -> Type{<:Real}

The number type of the parameters in the current evaluation: the element type of the parameter vector under EvalMode (Float64, Float32, or an AD number type during a gradient), and Float64 in every other mode.

Use it inside a model body, as paramtype(__mode__), wherever the model creates an array that will hold parameter values or that sets the precision of a prior:

x = Vector{paramtype(__mode__)}(undef, n)      # container for x[i] ~ ...
beta ~ MvNormal(zeros(paramtype(__mode__), k), I)

A Vector{Float64} container fails under AD, and a zeros(k) mean turns a Float32 run into Float64.

source
PracticalBayes.AutoPBForwardDiff — Type
AutoPBForwardDiff(; chunk=8)

A forward-mode AD backend built on Piste.jl, written to compile under juliac --trim. Needs import Piste and Julia 1.12.

import Piste
ldf = LogDensityFunction(model, layout, store, AutoPBForwardDiff(); θ0=θ0)

A gradient over K parameters costs ceil(K / chunk) model evaluations, so for models with many parameters a reverse-mode backend is faster. Float32 parameters stay Float32.

source
PracticalBayes.GradMode — Type
GradMode()

Backend that computes the gradient in closed form, for models recognised as generalised linear models. LogDensityFunction already uses it for a recognised model whatever backend you ask for; pass GradMode() to make that a requirement, so that construction throws if the model is not recognised.

A model is recognised when its linear predictor is visibly linear in the parameters: a sum of X * beta (data matrix times parameter vector), x .* b (data vector times scalar parameter), a[idx] (a parameter indexed by data), a scalar parameter, or data. A product of two parameters is not recognised. It cannot be used for a Gibbs block that holds only part of the model.

@model function poisson_reg(X, y)
    beta ~ MvNormal(zeros(size(X, 2)), I)
    y ~ arraydist(LogPoisson.(X * beta))
end

See also is_gradmode_compatible, check_gradmode.

source

PracticalBayes.static_nuts — Function
static_nuts(gradf!, x0, n_draws, n_warmup; delta=0.8, seed=1)

NUTS with a diagonal metric, adapting the step size towards acceptance rate delta and the metric during n_warmup iterations. Written without dependencies so that it compiles under juliac --trim.

gradf!(g, x) must write the gradient of the log density at x into g and return the log density. Warm-up draws are discarded. Returns a StaticHMCResult.

Warning

Its draws are too widely spread on low-dimensional targets; use static_hmc instead.

PracticalBayes.static_hmc — Function
static_hmc(gradf!, x0, inv_mass, eps, L, n_draws, n_warmup; seed=1, jitter=true)

HMC with a fixed diagonal inverse metric inv_mass, step size eps and up to L leapfrog steps, written without dependencies so that it compiles under juliac --trim. Nothing is adapted, so choose eps, L and inv_mass beforehand, for example by running it under the JIT and checking n_divergent and accept_rate.

gradf! is as for static_nuts. The first n_warmup draws are discarded. With jitter=true the step count is drawn from 1:L each iteration; jitter=false always takes L. Returns a StaticHMCResult.
